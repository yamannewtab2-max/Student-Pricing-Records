Build a clean, modern web application for managing student records and assigning prices to students.

The app must be EXTREMELY SIMPLE and minimal. The user should understand what to do immediately without reading long explanations.

Do NOT use popups/modals for the workflow. Every step should be a full-page screen.

## DESIGN

Create a premium, polished, minimal interface.

Style:
- Very clean and spacious
- Modern SaaS-style UI
- White/light background
- Subtle borders
- Soft shadows
- Rounded corners
- Elegant typography
- Excellent spacing
- Responsive on desktop, tablet, and mobile
- Subtle animations and transitions
- Professional but not complicated

IMPORTANT:
Use as few words as possible.
Do not add unnecessary descriptions, paragraphs, statistics, cards, or features.
Buttons should have short labels such as:
- Create record
- Next
- Back
- Save

The interface should be visually obvious rather than text-heavy.

# PAGE 1 — RECORDS

This is the start page.

Show a simple list of existing records.

At the top/right, have a prominent "+" button.

The + button should mean:
"Create new record"

If there are no records yet, show a very simple empty state with:
"+" / "Create record"

Do not add unnecessary explanations.

# PAGE 2 — CREATE RECORD

When the user clicks +, navigate to a full page.

Title:
"New record"

Show one input:

Record name

"September 2026"

Then a button:
"Next"

Also include a small "Back" button.

# PAGE 3 — SELECT STUDENTS

Title:
"Students"

Give the user two choices:

[ All students ]

[ Custom students ]

### ALL STUDENTS

If the user selects "All students", all students are selected automatically.

Then show:
"30 students selected"

And a:
"Next" button.

### CUSTOM STUDENTS

If the user selects "Custom students", show a search bar.

Search must work by:
- Student number
- Student name

Below the search bar, display the student list.

Each student should have a checkbox.

The user can select individual students.

Show the number selected, for example:
"8 selected"

Then:
"Next"

Keep this page very clean.

# PAGE 4 — PRICE

Title:
"Price"

Show the default price prominently:

1,500,000

Allow the user to choose:

[ Apply to all ]

[ Custom ]

The default price is:

1,500,000

Use proper Indonesian-style number formatting:
1.500.000

The user should be able to edit the default price.

### APPLY TO ALL

If "Apply to all" is selected:

Show one price input containing:

1.500.000

This same price will be assigned to every selected student.

Then:

"Next"

### CUSTOM

If "Custom" is selected:

Navigate to a clean full-page student pricing table.

Display ONLY the important information:

| Student | Level | Price |

Each row contains:
- Student name
- Level
- Editable price input

Example:

Abdul Karim | Tsaniy | [ 1.500.000 ]

The price input must be easy to edit.

Every selected student must appear in this list.

Then show:

"Next"

# PAGE 5 — REVIEW

Before saving, show a very clean review page.

Title:
"Review"

Show:

Record name
Number of students
Total amount

Then show the selected students and their assigned prices.

Keep the layout compact and readable.

Buttons:

"Back"

"Save record"

When "Save record" is clicked, save the record and return to the Records page.

# IMPORTANT UI RULES

Do not display parent names or phone numbers during the normal price-selection workflow unless needed.

The main student-selection and pricing screens should focus on:

Student number
Student name
Level
Price

The search bar should search:
- Student number
- Student name

Use checkboxes for student selection.

Use a sticky bottom navigation/action area for:
Back | Next

Make the "Next" button visually obvious.

Prevent moving to the next step if no students are selected.

Make price inputs numeric and automatically format values with Indonesian thousands separators.

Example:
1500000 → 1.500.000

Do not make the application feel like an accounting system with complicated menus.

The entire experience should feel like:

Create record
→ Name
→ Students
→ Price
→ Review
→ Save

That's it.

Focus on UX, simplicity, speed, and visual polish.
